# Timer: Phase Timing API

The phase timing API provides profiling capabilities for JIT compilation via the `JIT.Timer` struct.
It wraps the underlying `gcc_jit_timer` C pointer from libgccjit and allows consumers to measure and report time spent across different compilation phases. This feature was introduced in libgccjit ABI version 4 and is guarded at runtime by `JIT.Have_Timing_API`

## JIT.Timer Struct Overview

The `JIT.Timer` struct manages a phase timing session. Unlike many other wrapper structs in gccjitd, `JIT.Timer` does not define an `opCast!bool` overload; instead, instances are managed through constructors and explicit method calls

### Lazy Allocation via m_start

To avoid overhead when timing is unused, `JIT.Timer` employs a lazy allocation strategy. When a `JIT.Timer` is instantiated (e.g., via `JIT.Timer(bool start_timer)` or default construction), the underlying `gcc_jit_timer*` C handle is not immediately created.

Instead, a private static helper `m_start` checks the `m_constructed` flag and allocates the C timer via `gcc_jit_timer_new()` on the first operation.
Every public instance method (`push`, `pop`, `print`, `release`, and `get_timer`) invokes `m_start(this)` internally before interacting with the C API.

## Core Operations

`JIT.Timer` provides methods to manipulate the internal timing stack and output profiling results:

- `push(string item_name)()`: Pushes a named timing item onto the timing stack by calling `gcc_jit_timer_push`. The item name is passed as a static string template parameter.
- `pop(string item_name)()`: Pops the top item from the timing stack via `gcc_jit_timer_pop`
- `print(FILE* f_out)`: Outputs accumulated phase timing statistics to the specified C `FILE*` stream using `gcc_jit_timer_print`
- `release()`: Frees the underlying JIT timer resources via `gcc_jit_timer_release` and nullifies `m_timer`

## Association with Compilation Context

A `JIT.Timer` instance can be associated with a compilation `JIT.Context`. Although context-level timer integration is handled via helper mechanisms (such as the `JIT.AutoTime` RAII template which retrieves the timer via `ctxt.timer()`, the `JIT.Timer` struct itself operates as an independent profiling handle that can be passed across compilation tasks or queried directly.
